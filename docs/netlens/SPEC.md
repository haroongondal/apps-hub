# Technical Specification: NetLens (React Native edition)

> This specification replaces the original Kotlin-Multiplatform blueprint.
> The RN adaptation keeps every product requirement (FR/NFR/AC) and every OS
> invariant from `AGENTS.md`; only the hosting stack changes: shared code is
> TypeScript, platform code is native Kotlin (Android) / Swift (iOS) inside a
> local Expo module.

## 1. Tech Stack
- **Framework:** React Native 0.81.x inside Expo SDK 54, TypeScript 5.9.x.
- **Monorepo:** pnpm workspaces (`apps/*`, `apps/*/modules/*`, `packages/*`),
  `node-linker=hoisted` for Metro compatibility.
- **Shared logic:** `packages/core` — pure TypeScript (no React/RN imports),
  executed by Metro-apps and reusable by future Electron apps.
- **Native layer:** local Expo module `netlens-core` (Expo Modules API).
  - Android: Kotlin, `ConnectivityManager`/`LinkProperties`, `Socket` probes,
    `NsdManager`, `DatagramSocket`. Concurrency = `Semaphore(64)`.
  - iOS: Swift, `getifaddrs()` (en0), POSIX non-blocking connect + poll,
    `NWBrowser`, POS upgrades. Concurrency = 64 fixed worker dispatch queues.
- **Eventing:** native sweeper emits high-frequency events; JS subscribes and
  renders. `Flow<DiscoveredHost>` from the original design maps 1:1 to a
  `DiscoveredHost` event stream.
- **Tests:** `node --test` with native TypeScript stripping (no test framework
  dependency needed); Gradle JVM JUnit tests for native invariants.
- **Database (Phase 3):** `expo-sqlite` (schema below plus the version 1 name
  columns, see §4).

## 3. Native Module Contracts (`netlens-core`, Expo Modules API)

### 3.1 Interface & Gateway Detection (`getNetworkInterfaceInfo`)
Returns `{ localIp: string, cidrPrefix: number, gatewayIp: string | null }`.

- **Android (Kotlin):**
  - `ConnectivityManager.getActiveNetwork()` → `getLinkProperties(network)`.
  - IPv4 `LinkAddress` → `localIp` + `prefixLength` → `cidrPrefix`.
  - Gateway = first `route.isDefaultRoute` gateway address.
  - **CRITICAL:** do NOT use deprecated `WifiManager.getConnectionInfo()`.
  - Resilience fallback (NFR-3): if active network is absent but a legacy
    `NetworkInterface.getNetworkInterfaces()` IPv4 non-loopback iface exists,
    return it with `cidrPrefix` derived from the interface prefix; `gatewayIp`
    computed from interface route table when available, else `null`.

- **iOS (Swift):**
  - POSIX `getifaddrs()`, filter `en0` + `AF_INET` → `localIp`; `ifa_netmask`
    → popcount prefix.
  - Gateway: parse the IPv4 route table via `sysctl(CTL_NET, PF_ROUTE, …,
    NET_RT_DUMP)` and select the `RTF_GATEWAY` route with destination
    `0.0.0.0`; fallback `null`.

### 3.2 Host Discovery Engine (`startTcpScan(hostIps, ports, timeoutMs)`)
The JS layer owns subnet planning (see §3.5) and passes the explicit host IP
list; the native layer:1) validates `hostIps.length ≤ 256` (defensive clamp
re-assertion), 2) sweeps concurrently, 3) emits events in real time, 4)
resolves when the sweep finishes.

Per host: iterate ports sequentially; stop at the first non-offline outcome.

**Hard rule mapping (both platforms):**

| Native condition | Outcome | Meaning |
|---|---|---|
| `connect()` success | `open` | reachable, RTT measured |
| TCP **RST** → `ConnectException` (Kotlin) / `ECONNREFUSED` via `SO_ERROR` (Swift) | `refused` | **isReachable = true**, RTT = elapsed time to RST |
| `SocketTimeoutException` / `ETIMEDOUT` / poll timeout | `timeout` | offline for this port |
| `NoRouteToHostException` / `EHOSTUNREACH`, `ENETUNREACH`, `ENETDOWN` | `unreachable` | offline |

Events (real time):
- `onHostDiscovered { ip, isReachable, rttMs, winningPort, outcome }` — only
  for alive hosts (`open`|`refused`).
- `onScanComplete { durationMs, totalProbed, hostsFound, cancelled }`.

- **Android:** `Semaphore(64)` around IP iteration
  (`coroutineScope { for (ip in hostIps) { sem.acquire(); launch { … } } }`),
  `Socket().connect(InetSocketAddress(ip, port), timeoutMs)`.
- **iOS:** 64 fixed `DispatchQueue(label:…) `workers pulling host indexes from
  a shared locked cursor; POSIX non-blocking `connect()` + `poll(POLLOUT)`
  + `getsockopt(SOL_SOCKET, SO_ERROR)`; classify per the table above.

### 3.3 Service & Hostname Enrichment (`startServiceDiscovery(timeoutMs)`)
Combined mDNS + SSDP sweep emitting `onServiceDiscovered` events:

```ts
onServiceDiscovered {
  kind: 'mdns' | 'ssdp' | 'mdns-instance',
  serviceName?: string,   // mdns: service TYPE from meta-query (e.g. "_http._tcp")
  host?: string,          // ssdp: the responder's address; mdns-instance: the instance's IPv4
  location?: string, server?: string, usn?: string,  // ssdp headers
  instanceName?: string,  // mdns-instance: the name before cleaning (§3.6)
  serviceType?: string    // mdns-instance: type it answered for (e.g. "_airplay._tcp")
}
```

- **mDNS:**
  - Android: `NsdManager.discoverServices("_services._dns-sd._udp.local.",
    PROTOCOL_DNS_SD, listener)`; each `onServiceFound` is a service *type*.
    Acquire `WifiManager.MulticastLock` first (AGENTS rule 4), release in
    `finally`.
  - iOS: `NWBrowser(for: .bonjour(type: "_services._dns-sd._udp",
    domain: "local"), using: NWParameters())`.
- **SSDP (both platforms):** UDP multicast `M-SEARCH` —
  `HOST: 239.255.255.250:1900`, `MAN: "ssdp:discover"`, `MX: 2`,
  `ST: ssdp:all` — then parse `LOCATION`, `SERVER`, `USN` (and `NT`) from
  responses within the window.
- Completion: `onServiceScanComplete { mdnsCount, ssdpCount, cancelled }`.

### 3.4 Cancellation
`stopTcpScan()` / `stopServiceDiscovery()` cancel native sweeps; a cancelled
sweep still emits `on…Complete { cancelled: true }` so JS state machines stay
simple.

### 3.5 Subnet Planning (TypeScript, `packages/core`)
Single source of truth for the sweep list:
- `parseIpv4` / `formatIpv4` — uint32 round-trip (rejects malformed input).
- `computeSubnetForHost(hostIp, requestedPrefix)` — **clamps `requestedPrefix`
  to a maximum of `/24` around the host IP** (NFR-1): any prefix `> 24`
  (e.g., `/16`, `/32`) is widened to the containing `/24`. Returns
  `{ hostIp, prefix, networkIp, broadcastIp, hosts: string[], clamped }`
  excluding the network (`…0`) and broadcast (`…255`) addresses → 254 targets
  for a /24.
- The engine passes `hosts` to `startTcpScan`; native re-validates the ≤256
  bound defensively.

### 3.6 Device Names (`resolveDeviceNames`, after the sweep)
After the sweep is reconciled and the list is on screen, `ScannerScreen` calls
`resolveDeviceNames` (`packages/core/src/name-resolver.ts`) for every device
seen this scan. It is best effort: nothing rejects, and a failed lookup means
no name. Parsing and sanitising are pure TypeScript (`device-names.ts`,
`name-formats.ts`). For PTR, NetBIOS and the SSDP description, native code only
moves bytes; for mDNS it also browses and resolves instances.

**Four sources** (a device gets whichever of them it answers):

1. **Reverse DNS (PTR).** A raw DNS PTR query for `d.c.b.a.in-addr.arpa` goes
   straight to the gateway on UDP 53, not through the system resolver. The
   router usually knows the name a device gave DHCP. No gateway, no PTR
   lookup. The reply must echo the query id, have the response bit set and
   RCODE 0. Stored as `hostname`.
2. **mDNS instance names.** Native code browses instances of six types:
   `_googlecast._tcp`, `_airplay._tcp`, `_ipp._tcp`, `_smb._tcp`, `_hap._tcp`
   and `_companion-link._tcp`, resolves each to an IPv4 address, and emits
   `onServiceDiscovered { kind: 'mdns-instance', host, instanceName,
   serviceType }` (see §3.3). At most 32 resolves per scan, 1,500 ms each. Instances
   are collected during the 4 s service-discovery window, alongside the sweep;
   an instance resolved after the window closes is lost.
   - Android: a type is browsed only when the meta-query reports it, with at
     most 6 browsers (`MAX_BROWSERS`; NSD allows a client about 10
     outstanding requests: 1 meta browser + 6 + 1 resolve). Resolves run one
     at a time, because `NsdManager` before API 34 rejects a second resolve
     while one is active. On API 34+ the first IPv4 in `hostAddresses` wins.
   - iOS: the same six types are browsed directly. `NSBonjourServices` (in
     `app.json` and `Info.plist`) lists them plus `_services._dns-sd._udp` and
     `_http._tcp`.
   - The screen keeps the first usable name per host. Stored as `mdnsName`.
3. **SSDP device description.** The `LOCATION` URL from the SSDP reply is
   fetched with `tcpFetch` as a raw `HTTP/1.0` GET. The reply is untrusted,
   so `ssdpDescriptionRequest` and the parser enforce:
   - the URL host is the same private IPv4 (10/8, 172.16/12, 192.168/16,
     169.254/16) that sent the SSDP reply;
   - `http` only; port 1..65535 (80 when absent);
   - the path is printable ASCII (`\x21-\x7E`);
   - no redirects: only status 200 is read;
   - 64 KB cap on the total bytes read, headers included
     (`SSDP_DESCRIPTION_MAX_BYTES`);
   - a document containing `<!DOCTYPE` or `<!ENTITY` is ignored. The fields
     are found by a linear string scan, not an XML parser; only the five
     predefined entities are decoded.

   `friendlyName` is stored as `friendlyName`; `manufacturer` plus
   `modelName` is stored as `model`.
4. **NetBIOS node status.** A name-status request (type `0x21`) goes to the
   device on UDP 137. The first unique name with suffix `0x00` is the name
   (trailing spaces trimmed). Stored as `netbiosName`.

**Native primitives** (the four-place contract: `NetLensNativeBinding`, the
`createNetLensNativeBinding` adapter, Kotlin, Swift). `timeoutMs` is 1..10000
on both platforms.

| Function | Behaviour |
|---|---|
| `udpRequest(ip, port, payload, timeoutMs) → number[] \| null` | Sends one datagram and returns the first reply that comes from that same `ip:port`; null on timeout or error. Android binds the socket to Wi-Fi for private targets when it can and falls back to the default route when binding fails (a VPN can refuse it). |
| `tcpFetch(ip, port, request, timeoutMs, maxBytes) → string \| null` | Connects, writes `request`, reads until EOF, `maxBytes` or the deadline, decodes UTF-8. Null when the connect fails or no byte arrived. Android uses the Wi-Fi socket factory. |

**Display order** (`displayNameFor`): custom name, mDNS instance name, SSDP
`friendlyName`, NetBIOS name, first label of the hostname (an IP-literal
hostname is skipped), SSDP `SERVER` string (`vendorOrModel`), IP. `model` is
not part of the order; the detail sheet shows each source on its own row
(Hostname, Bonjour name, UPnP name, Model, Windows name, Vendor or model).

**Sanitising.** Every name passes `sanitizeName`: control characters (C0 other
than whitespace, DEL, C1) and bidi embedding, override and isolate characters
(U+202A..202E, U+2066..2069) are removed; whitespace runs collapse to one
space; the result is trimmed and capped at 64 code points (never cutting a
surrogate pair). A name with no visible character left (only spaces,
soft hyphens, zero-width characters) counts as no name. ZWJ, ZWNJ, LRM and RLM
stay. mDNS names first go through `cleanMdnsInstanceName`: DNS-SD escapes
decode (`\DDD` is a decimal character code, `\X` is `X`), then an AirPlay
MAC prefix (`A1B2C3D4E5F6@`) is dropped.

**Timing.** The device list appears when the sweep is reconciled, so naming
never slows the sweep (NFR-1). Then 16 targets are in flight at a time
(`NAME_CONCURRENCY`). Per target, PTR, NetBIOS and description lookups run in
parallel, each with a 1,500 ms native timeout plus a 250 ms JS guard that gives
up on a call that never settles: at most 1.75 s per target, so `n` devices
take at most `ceil(n / 16) * 1.75` s. Each target's names are merged into its
row and saved as soon as they arrive, so names fill in one by one. A result
from a superseded scan is dropped.

**Identity.** Names never change a device's identity key.
`deriveIdentityKey` still reads only USN, then enrichment hostname, then IP,
and the scanner passes no hostname into it, so `applyDeviceNames` touches
the five name fields and nothing else. Known devices keep their rows and no
"New" badge appears after the update (FR-4).

## 4. Database Schema (`expo-sqlite`, Phase 3)

```sql
CREATE TABLE networks (
  network_id TEXT PRIMARY KEY,          -- hash of GatewayIP + CIDR (or BSSID if granted)
  gateway_ip TEXT NOT NULL,
  subnet_cidr TEXT NOT NULL,
  custom_name TEXT,
  last_scanned_at INTEGER NOT NULL
);

CREATE TABLE devices (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  network_id TEXT NOT NULL,
  identity_key TEXT NOT NULL,           -- mDNS instance/hostname or MAC; fallback IP
  last_ip TEXT NOT NULL,
  hostname TEXT,
  custom_name TEXT,
  vendor_or_model TEXT,
  open_ports_csv TEXT NOT NULL,
  mdns_services_csv TEXT NOT NULL,
  is_trusted INTEGER NOT NULL DEFAULT 0,
  first_seen_at INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL,
  UNIQUE (network_id, identity_key)
);
```

**Migration (`PRAGMA user_version`).** Version 1 adds four nullable `TEXT`
columns to `devices`: `mdns_name`, `friendly_name`, `model`, `netbios_name`
(`hostname` already existed). `openDeviceStore` runs the `ALTER TABLE`
statements and sets `user_version = 1` in one transaction, and skips them when
`user_version` is already 1 or higher. Existing rows keep every value, with the
new columns null until a scan names them. See §3.6.

## 5. Diagnostic Engine ("Why is my Wi-Fi slow?" — Phase 2)

- Execute 10 sequential probes (200ms interval):
  1. `gatewayIp` (TCP port 80/53/443 or `isReachable`)
  2. `1.1.1.1:53` (Cloudflare TCP handshake latency)
  3. `8.8.8.8:53` (Google DNS TCP handshake latency)
- **Metrics:** `avgRttMs = rtts.average()`; `jitterMs = rtts.zipWithNext { a, b -> abs(a-b) }.average()`;
  `packetLossPct = failedCount / total * 100`.
- **Diagnosis heuristic:**
  - gateway `avgRttMs > 30` OR `jitterMs > 15` OR `packetLossPct > 2` → `LOCAL_WIFI_CONGESTION`
  - else WAN `avgRttMs > 120` OR `packetLossPct > 2` → `ISP_WAN_DEGRADATION`
  - else `dnsResolveMs > 150` → `SLOW_DNS_SERVER`
  - else `HEALTHY`
- TCP handshake RTT counts **both** a successful connect and `ECONNREFUSED`
  (RST) as valid RTT measurements — same reason as §3.2.
- DNS latency via native host-resolution bridge (Android `InetAddress`,
  iOS `getaddrinfo`).
