# Technical Specification: NetLens (React Native edition)

> This specification replaces the original Kotlin-Multiplatform blueprint.
> The RN adaptation keeps every product requirement (FR/NFR/AC) and every OS
> invariant from `AGENTS.md`; only the hosting stack changes: shared code is
> TypeScript, platform code is native Kotlin (Android) / Swift (iOS) inside a
> local Expo module.

## 1. Tech Stack
- **Framework:** React Native 0.81.x inside Expo SDK 54, TypeScript 5.9.x.
- **Monorepo:** pnpm workspaces (`apps/*`, `apps/*/modules/*`, `packages/*`),
  `node-linker=hoisted` for Metro compatibility.
- **Shared logic:** `packages/core` — pure TypeScript (no React/RN imports),
  executed by Metro-apps and reusable by future Electron apps.
- **Native layer:** local Expo module `netlens-core` (Expo Modules API).
  - Android: Kotlin, `ConnectivityManager`/`LinkProperties`, `Socket` probes,
    `NsdManager`, `DatagramSocket`. Concurrency = `Semaphore(64)`.
  - iOS: Swift, `getifaddrs()` (en0), POSIX non-blocking connect + poll,
    `NWBrowser`, POS upgrades. Concurrency = 64 fixed worker dispatch queues.
- **Eventing:** native sweeper emits high-frequency events; JS subscribes and
  renders. `Flow<DiscoveredHost>` from the original design maps 1:1 to a
  `DiscoveredHost` event stream.
- **Tests:** `node --test` with native TypeScript stripping (no test framework
  dependency needed); Gradle JVM JUnit tests for native invariants.
- **Database (Phase 3):** `expo-sqlite` (schema below unchanged in columns).

## 3. Native Module Contracts (`netlens-core`, Expo Modules API)

### 3.1 Interface & Gateway Detection (`getNetworkInterfaceInfo`)
Returns `{ localIp: string, cidrPrefix: number, gatewayIp: string | null }`.

- **Android (Kotlin):**
  - `ConnectivityManager.getActiveNetwork()` → `getLinkProperties(network)`.
  - IPv4 `LinkAddress` → `localIp` + `prefixLength` → `cidrPrefix`.
  - Gateway = first `route.isDefaultRoute` gateway address.
  - **CRITICAL:** do NOT use deprecated `WifiManager.getConnectionInfo()`.
  - Resilience fallback (NFR-3): if active network is absent but a legacy
    `NetworkInterface.getNetworkInterfaces()` IPv4 non-loopback iface exists,
    return it with `cidrPrefix` derived from the interface prefix; `gatewayIp`
    computed from interface route table when available, else `null`.

- **iOS (Swift):**
  - POSIX `getifaddrs()`, filter `en0` + `AF_INET` → `localIp`; `ifa_netmask`
    → popcount prefix.
  - Gateway: parse the IPv4 route table via `sysctl(CTL_NET, PF_ROUTE, …,
    NET_RT_DUMP)` and select the `RTF_GATEWAY` route with destination
    `0.0.0.0`; fallback `null`.

### 3.2 Host Discovery Engine (`startTcpScan(hostIps, ports, timeoutMs)`)
The JS layer owns subnet planning (see §3.5) and passes the explicit host IP
list; the native layer:1) validates `hostIps.length ≤ 256` (defensive clamp
re-assertion), 2) sweeps concurrently, 3) emits events in real time, 4)
resolves when the sweep finishes.

Per host: iterate ports sequentially; stop at the first non-offline outcome.

**Hard rule mapping (both platforms):**

| Native condition | Outcome | Meaning |
|---|---|---|
| `connect()` success | `open` | reachable, RTT measured |
| TCP **RST** → `ConnectException` (Kotlin) / `ECONNREFUSED` via `SO_ERROR` (Swift) | `refused` | **isReachable = true**, RTT = elapsed time to RST |
| `SocketTimeoutException` / `ETIMEDOUT` / poll timeout | `timeout` | offline for this port |
| `NoRouteToHostException` / `EHOSTUNREACH`, `ENETUNREACH`, `ENETDOWN` | `unreachable` | offline |

Events (real time):
- `onHostDiscovered { ip, isReachable, rttMs, winningPort, outcome }` — only
  for alive hosts (`open`|`refused`).
- `onScanComplete { durationMs, totalProbed, hostsFound, cancelled }`.

- **Android:** `Semaphore(64)` around IP iteration
  (`coroutineScope { for (ip in hostIps) { sem.acquire(); launch { … } } }`),
  `Socket().connect(InetSocketAddress(ip, port), timeoutMs)`.
- **iOS:** 64 fixed `DispatchQueue(label:…) `workers pulling host indexes from
  a shared locked cursor; POSIX non-blocking `connect()` + `poll(POLLOUT)`
  + `getsockopt(SOL_SOCKET, SO_ERROR)`; classify per the table above.

### 3.3 Service & Hostname Enrichment (`startServiceDiscovery(timeoutMs)`)
Combined mDNS + SSDP sweep emitting `onServiceDiscovered` events:

```ts
onServiceDiscovered {
  kind: 'mdns' | 'ssdp',
  serviceName?: string,   // mdns: service TYPE from meta-query (e.g. "_http._tcp")
  host?: string, location?: string, server?: string, usn?: string  // ssdp headers
}
```

- **mDNS:**
  - Android: `NsdManager.discoverServices("_services._dns-sd._udp.local.",
    PROTOCOL_DNS_SD, listener)`; each `onServiceFound` is a service *type*.
    Acquire `WifiManager.MulticastLock` first (AGENTS rule 4), release in
    `finally`.
  - iOS: `NWBrowser(for: .bonjour(type: "_services._dns-sd._udp",
    domain: "local"), using: NWParameters())`.
- **SSDP (both platforms):** UDP multicast `M-SEARCH` —
  `HOST: 239.255.255.250:1900`, `MAN: "ssdp:discover"`, `MX: 2`,
  `ST: ssdp:all` — then parse `LOCATION`, `SERVER`, `USN` (and `NT`) from
  responses within the window.
- Completion: `onServiceScanComplete { mdnsCount, ssdpCount, cancelled }`.

### 3.4 Cancellation
`stopTcpScan()` / `stopServiceDiscovery()` cancel native sweeps; a cancelled
sweep still emits `on…Complete { cancelled: true }` so JS state machines stay
simple.

### 3.5 Subnet Planning (TypeScript, `packages/core`)
Single source of truth for the sweep list:
- `parseIpv4` / `formatIpv4` — uint32 round-trip (rejects malformed input).
- `computeSubnetForHost(hostIp, requestedPrefix)` — **clamps `requestedPrefix`
  to a maximum of `/24` around the host IP** (NFR-1): any prefix `> 24`
  (e.g., `/16`, `/32`) is widened to the containing `/24`. Returns
  `{ hostIp, prefix, networkIp, broadcastIp, hosts: string[], clamped }`
  excluding the network (`…0`) and broadcast (`…255`) addresses → 254 targets
  for a /24.
- The engine passes `hosts` to `startTcpScan`; native re-validates the ≤256
  bound defensively.

## 4. Database Schema (`expo-sqlite`, Phase 3)

```sql
CREATE TABLE networks (
  network_id TEXT PRIMARY KEY,          -- hash of GatewayIP + CIDR (or BSSID if granted)
  gateway_ip TEXT NOT NULL,
  subnet_cidr TEXT NOT NULL,
  custom_name TEXT,
  last_scanned_at INTEGER NOT NULL
);

CREATE TABLE devices (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  network_id TEXT NOT NULL,
  identity_key TEXT NOT NULL,           -- mDNS instance/hostname or MAC; fallback IP
  last_ip TEXT NOT NULL,
  hostname TEXT,
  custom_name TEXT,
  vendor_or_model TEXT,
  open_ports_csv TEXT NOT NULL,
  mdns_services_csv TEXT NOT NULL,
  is_trusted INTEGER NOT NULL DEFAULT 0,
  first_seen_at INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL,
  UNIQUE (network_id, identity_key)
);
```

## 5. Diagnostic Engine ("Why is my Wi-Fi slow?" — Phase 2)

- Execute 10 sequential probes (200ms interval):
  1. `gatewayIp` (TCP port 80/53/443 or `isReachable`)
  2. `1.1.1.1:53` (Cloudflare TCP handshake latency)
  3. `8.8.8.8:53` (Google DNS TCP handshake latency)
- **Metrics:** `avgRttMs = rtts.average()`; `jitterMs = rtts.zipWithNext { a, b -> abs(a-b) }.average()`;
  `packetLossPct = failedCount / total * 100`.
- **Diagnosis heuristic:**
  - gateway `avgRttMs > 30` OR `jitterMs > 15` OR `packetLossPct > 2` → `LOCAL_WIFI_CONGESTION`
  - else WAN `avgRttMs > 120` OR `packetLossPct > 2` → `ISP_WAN_DEGRADATION`
  - else `dnsResolveMs > 150` → `SLOW_DNS_SERVER`
  - else `HEALTHY`
- TCP handshake RTT counts **both** a successful connect and `ECONNREFUSED`
  (RST) as valid RTT measurements — same reason as §3.2.
- DNS latency via native host-resolution bridge (Android `InetAddress`,
  iOS `getaddrinfo`).
