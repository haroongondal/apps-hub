# Technical specification: Design Editor media tools and the mobile Design Editor

Requirements (FR, NFR, AC and the six data-safety rules) are in `docs/design-editor/PRD.md`.
Facts and sources are in `docs/design-editor/RESEARCH.md`; "R§n" below points there. Items
marked **spike** are settled on the owner's phone in Phase 1 (§18). Written 2026-10-31.

## 1. Tech stack

- **Mac:** the existing Electron app `apps/design-editor` (Electron 44.8.0 = Node 24.22.0 and
  Chrome 152, R§11), plain JavaScript, Fabric.js 7.4.0, pdf-lib 1.17.1. Media jobs run as
  FFmpeg/FFprobe child processes of the main process. Not a Store app; built locally with
  `pnpm --filter design-editor dist`.
- **Android:** a new Expo SDK 54 app `apps/design-editor-mobile` (React Native 0.81.5, TypeScript
  5.9, expo-router like PDF Editor). The canvas is the shared editor page in
  `react-native-webview`. Media jobs run in one Expo local module, `design-media` (Kotlin), on
  Media3 Transformer 1.11.1 and the platform's `MediaExtractor`/`MediaMuxer`.
- **Shared:** `packages/media-core`, pure erasable TypeScript, `node --test`. Used by the Mac main
  process (imported as `.ts` with no build step, R§11 verified) and by the React Native shell.
  `packages/design-editor-engine`: the editor page, shared by both shells.
- **Principle: native code owns running jobs; TypeScript owns decisions.** `media-core` validates
  jobs and makes every plan (resolution, bitrate, container, names). The Mac main process and the
  Kotlin service execute plans, measure results and apply the one rule that needs a runtime
  number (the retry rule, §10.4), which Kotlin mirrors and tests against `media-core`'s fixtures.
  React Native JS pauses in the background (Deputy, R§9.1), so it never drives a running job.
- **Min Android:** API 35 (`android.minSdkVersion=35` in `gradle.properties`, PRD Q5), so the
  queue has one foreground service type, `mediaProcessing`, and `Service.onTimeout(int, int)`.
- **FOSS only**, no telemetry; every new dependency is in §3 and needs the owner's approval.

## 4. Process model and data flow

- **Mac:** one main process. `media.js` keeps the queue and at most one FFmpeg child at a time.
  The canvas window and the Media tools window are both renderers using the same preload. The
  queue lives as long as the app; quitting with a job running asks first (PRD AC-12). No queue
  persistence across launches (jobs are minutes long on a Mac).
- **Android:** one app process. `MediaJobService` (foreground, `mediaProcessing`) owns the queue
  while any job is queued or running and stops itself when the queue drains. The React Native UI
  reads the queue through the module and gets events while it is in the foreground. The canvas
  WebView never sees media.

Data flow per job:

```
UI (renderer or RN) ──pick──▶ native picker ──▶ input id/URI + MediaInfo (probe)
UI ──JobSpec──▶ media-core.validate + plan ──Plan──▶ UI shows plan ──Start──▶
Mac:     main.js media.js: spawn ffmpeg per plan → temp file → size check/retry → rename into folder
Android: module.enqueue(planJson) → MediaJobService → runner → temp file → size check/retry → MediaStore
events ──▶ UI (progress, state, outputs)
```

### 5.1 Types (`types.ts`, erasable TS only)

```ts
export type Platform = 'mac' | 'android';
export type Tool = 'size' | 'quality' | 'clip' | 'audio' | 'gif' | 'convert';
export type Codec = 'h264' | 'hevc' | 'vp8' | 'vp9' | 'av1' | 'mpeg4' | 'prores'
  | 'aac' | 'alac' | 'mp3' | 'opus' | 'vorbis' | 'ac3' | 'eac3' | 'flac' | 'pcm' | 'dts' | 'truehd' | 'other';

export interface Track {
  index: number;            // container track index (FFprobe stream index / MediaExtractor track)
  kind: 'video' | 'audio' | 'other';
  codec: Codec;
  width?: number; height?: number; fps?: number; rotation?: 0 | 90 | 180 | 270; hdr?: boolean;
  channels?: number; sampleRate?: number; language?: string; bitrate?: number;
}
export interface MediaInfo {
  id: string;               // Mac: main-process input id; Android: the content:// URI
  name: string; bytes: number; durationS: number;
  container: 'mp4' | 'mov' | 'mkv' | 'webm' | 'mp3' | 'm4a' | 'ogg' | 'wav' | 'flac' | 'other';
  tracks: Track[];
}
export type Encoder = 'hw-h264' | 'hw-hevc' | 'x264';          // hw = MediaCodec or VideoToolbox
export interface Rung { shortSide: number; fps: number }

export interface SizePlan {
  tool: 'size'; targetBytes: number; encoder: Encoder; rung: Rung;
  width: number; height: number; videoBps: number; audio: { mode: 'copy' } | { mode: 'aac'; bps: number } | { mode: 'none' };
  overheadBytes: number; plannedVideoBytes: number; plannedBytes: number;
  attempt: 1 | 2 | 3; margin: number;
}
export type Refusal =
  | { ok: false; reason: 'too-long'; maxDurationS: number }
  | { ok: false; reason: 'no-video' | 'gave-up' | 'invalid'; detail?: string };
export type Planned<P> = { ok: true; plan: P } | Refusal;

export interface ClipPlan { tool: 'clip'; mode: 'copy' | 'exact'; startS: number; endS: number; keyframeS: number; container: string; ext: string; tracks: number[] }
export interface AudioPlan { tool: 'audio'; trackIndex: number; mode: 'copy' | 'raw' | 'wav' | 'aac'; container: 'mp4' | 'ogg' | 'webm' | 'mka' | 'raw'; ext: string; bps?: number }
export interface GifPlan { tool: 'gif'; startS: number; endS: number; width: number; fps: number; targetBytes?: number; attempt: number }
export interface ConvertPlan { tool: 'convert'; mode: 'remux' | 'transcode'; container: string; ext: string; video?: { encoder: Encoder; quality: number }; audio?: { codec: Codec; bps?: number } }
export interface QualityPlan { tool: 'quality'; encoder: Encoder; rung: Rung; width: number; height: number; quality: number /* VT -q:v, or bpp on Android */ }
export type Plan = SizePlan | QualityPlan | ClipPlan | AudioPlan | GifPlan | ConvertPlan;

export type JobState = 'queued' | 'running' | 'done' | 'failed' | 'cancelled' | 'interrupted' | 'paused';
export interface Output { name: string; ref: string /* Mac path or Android content URI */; bytes: number; note?: string /* "converted to AAC" */ }
export interface Job {
  id: string; inputId: string; inputName: string; plan: Plan; state: JobState;
  progress: number /* 0..1 of the current attempt */; attempt: number;
  outputs: Output[]; error?: string; startedAt?: number; finishedAt?: number;
}
export type QueueEvent =
  | { type: 'enqueue'; jobs: Job[] } | { type: 'start'; id: string; at: number }
  | { type: 'progress'; id: string; fraction: number } | { type: 'retry'; id: string; plan: Plan }
  | { type: 'done'; id: string; outputs: Output[]; at: number } | { type: 'fail'; id: string; error: string; at: number }
  | { type: 'cancel'; id: string | 'all' } | { type: 'interrupt' } | { type: 'pause'; reason: 'time-limit' } | { type: 'resume' };
```

### 6.1 Preload (`preload.cjs`, the only bridge)

```js
    preview: inputId => ipcRenderer.invoke('media-preview', inputId),  // → URL for <video>, or null (§11)
    enqueue: specs => ipcRenderer.invoke('media-enqueue', specs),      // specs: { inputId, folderId, tool, options }[] → job ids
    cancel: id => ipcRenderer.invoke('media-cancel', id),              // job id or 'all'
    reveal: jobId => ipcRenderer.invoke('media-reveal', jobId),        // shell.showItemInFolder
    open: jobId => ipcRenderer.invoke('media-open', jobId),            // shell.openPath
    onEvent: fn => ipcRenderer.on('media-event', (_, e) => fn(e)),     // { type: 'queue', jobs } on every change
  },

```

### 6.2 Rules main enforces

- **The renderer never sends a path.** `media-pick` stores each chosen file in
  `inputs: Map<id, path>` and returns ids; `media-pick-folder` does the same for
  `folders: Map<id, path>`. Every handler resolves ids and rejects unknown ones (PRD AC-11).
- Outputs are built in main: `path.join(folder, outputName(...))`, checked with
  `path.dirname(out) === folder` and `!inputs.has(out)`; written as `<out>.part` and renamed on
  success. Existing files are never replaced (`exists` callback to `outputName`).
- Temporary files (two-pass logs, retry attempts) live in `app.getPath('temp')/design-editor-media/<jobId>/`
  and are deleted when the job ends, whatever the outcome.
- `media-plan` and `media-enqueue` run `validateSpec` before planning; a failing spec returns its
  errors and starts nothing.

### 6.3 `media.js` (plain JS, about 250 lines)

- Imports `./vendor/media-core/index.ts` (symlink; type stripping, R§11).
- `run(job)`: `spawn(FFMPEG, ffmpegArgs(plan, input, tmpOut), { stdio: ['pipe', 'pipe', 'pipe'] })`,
  feeding stdout to `parseProgress`; stderr kept (last 4 KB) for the error message.
- Cancel: `child.stdin.write('q')`, `SIGKILL` after 3 s, delete `.part` and temp dir.
- After a size job: `fs.stat(tmpOut).size` → `nextSizeAttempt` → run again or rename.
- `powerSaveBlocker.start('prevent-app-suspension')` while the queue is non-empty; stopped when it drains.
- `app.on('before-quit')`: if a job runs, show a message box ("A media job is running. Quit and
  stop it?"); on Quit, cancel all and wait for children to exit.
- Encoder stats (`userData/media-stats.json`): `{ "<encoder>": [ratio, …] }`, last 5 kept; the
  median is passed to `planSize` as `correction`.

### 6.4 Menu

`File → Media Tools…` (`id: 'media'`, ⇧⌘M) opens or focuses the Media tools window
(`media.html`, same preload, `will-navigate` blocked). The canvas rail gets a "Media" button
(desktop page only; on Android the Media tab replaces it) that sends the same command. The e2e suite clicks `media` through `Menu.getMenuItemById` (CLAUDE.md:
ids are API).

### 6.5 FFmpeg binaries

- `pnpm --filter design-editor ffmpeg` runs `scripts/fetch-ffmpeg.mjs`: downloads the pinned
  `ffmpeg` and `ffprobe` zips (URL and SHA-256 constants, recorded in Phase 2 from
  ffmpeg.martin-riedl.de, PRD Q2), verifies the hashes, unzips with `ditto -x -k`, `chmod +x`, runs
  `ffmpeg -version` and writes the version and configure line to `vendor/ffmpeg/VERSION`.
- Missing binaries: the Media tools window shows a `Notice`: "FFmpeg isn't set up. Run
  `pnpm --filter design-editor ffmpeg`, then reopen this window."
- If `VERSION`'s configure line contains `--enable-nonfree`, the script refuses (that build could
  not be shared even under the GPL).
- Licence notice in the Media tools window's About row: FFmpeg version, GPL, x264.

## 8. Job model and queue

```
queued ──start──▶ running ──done──▶ done
   ▲                 │ ├──fail──▶ failed ──"Try again" (new job, same plan)──▶ queued
   │                 │ ├──cancel──▶ cancelled
   │                 │ ├──pause (onTimeout)──▶ paused ──resume──▶ queued
   └──resume─────────┘ └──process died (seen at load)──▶ interrupted ──resume──▶ queued
```

- One job runs at a time on each platform (one hardware encode session, predictable memory).
- `attempt` counts size and GIF retries inside `running`; a retry emits `{ type: 'retry' }` with
  the new plan.
- Persistence (Android only): `filesDir/media-queue.json`, written on every transition. On load,
  any `running` job becomes `interrupted` (PRD AC-7). Nothing resumes without the owner.
- `cancel('all')` cancels the running job and every queued one.

| Tool | Runner | Details |
| --- | --- | --- |

## 10. Target-size algorithm

### 10.1 Inputs

`info` (duration, video track, audio tracks), `targetBytes`, `encoder`, `correction`
(per-encoder median ratio, default 1.0), `maxFps` (30).

### 10.2 Steps (`planSize`)

1. No video track → refuse `no-video` (audio-only fits use the audio tool).
2. `margin` = 0.97 for `x264` (two-pass), 0.90 for `hw-*`.
3. `overheadBytes = 65,536 + 0.01 × targetBytes` (**calibrated in Phase 1**: measure
   `actual − (video bytes + audio bytes)` on five outputs and replace the constants).
4. `totalBps = (targetBytes × margin − overheadBytes) × 8 / durationS`.
5. Audio: copy when the first audio track is AAC with a known bitrate ≤ the tier; else AAC at
   128k (total ≥ 1,000k), 96k (≥ 500k), 64k (≥ 250k), else 48k; none if there is no audio.
6. `videoBps = (totalBps − audioBps) / correction`.
7. Frame rate = min(source fps, `maxFps`). Walk `LADDER` (1080/30, 720/30, 540/30, 480/30,
   360/30, 360/24, 240/24, skipping rungs above the source) and take the first whose
   `videoBps / (w × h × fps)` ≥ `FLOOR[encoder]` (hw-h264 0.05, hw-hevc 0.035, x264 0.04;
   **assumed**, tuned in Phase 1). Width keeps the aspect ratio, rounded to even (16 for hw).
8. None passes, and the lowest rung is below half the floor → refuse `too-long` with
   `maxDurationS = (targetBytes × margin − overheadBytes) × 8 / (FLOOR × w × h × fps / 2 + 48,000)`
   at the lowest rung. Otherwise use the lowest rung.
9. `plannedVideoBytes = videoBps × durationS / 8`; `plannedBytes` adds audio and overhead.

### 10.3 Worked numbers

R§6.6 has the full arithmetic; the `budget-cases.json` fixture encodes exactly these cases:

| Case | Result |
| --- | --- |
| 60 s 1080p30, 20 MB, hw-h264 | 720p30, video 2,236,595 bit/s, audio 128k, planned ≈ 18.0 MB |
| Same, hw-hevc | 1080p30, same bitrates |
| 180 s, 20 MB, hw-h264 / hw-hevc | 480p30 / 540p30, video 692,198 bit/s, audio 96k |
| 30 min, 20 MB | refused, `maxDurationS` ≈ 1,297 (about 21 minutes) |
| 60 s 1080p60, 50 MB, x264 | fps capped to 30; 1080p30 (video ≈ 6.3 Mbit/s) |

### 10.4 Retry (`nextSizeAttempt`, mirrored in `RetryRule.kt`)

```
if actualBytes ≤ plan.targetBytes            → ok, publish
if plan.attempt == 3                         → refuse 'gave-up'
actualVideoBytes = actualBytes − audioBytes − overheadBytes
videoBps' = plan.videoBps × plan.plannedVideoBytes / actualVideoBytes × 0.97
re-run step 7 with videoBps' (the rung may drop), attempt + 1
```

After every finished size job, `actualVideoBytes / plannedVideoBytes` of attempt 1 is appended to
the encoder's stats (§6.3, `EncoderStats`).

### 10.5 GIF fit

`GIF_LADDER` = 480/12, 360/12, 320/10, 240/10 (width/fps). Attempt 1 uses the chosen settings;
over the target, step down one rung; at most 4 attempts; then refuse `gave-up`.

## 11. Background execution

### 11.1 Android: `MediaJobService`

- Manifest (module): `<service android:name=".android.MediaJobService" android:exported="false"
  android:foregroundServiceType="mediaProcessing" />`, permissions `FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_MEDIA_PROCESSING`; app `POST_NOTIFICATIONS`.
- Started with `startForegroundService` from `enqueue` (the app is in the foreground then);
  `startForeground(id, notification, FOREGROUND_SERVICE_TYPE_MEDIA_PROCESSING)` at once.
- Runs jobs on a `HandlerThread` (Transformer needs a Looper). Stops itself when nothing is queued.
- `onTimeout(startId, fgsType)`: cancel the running job's export, mark it `paused`
  (`time-limit`), persist, `stopSelf()` within the same call. `resume()` later re-queues it.
- `onTaskRemoved`: nothing to do; the service keeps running (stock Android). **Spike S3** checks
  HyperOS.
- Notification channel "Media jobs" (low importance, no sound): title "Compressing 2 of 5",
  text = file name, `setProgress(100, pct, false)`, `setOngoing(true)`, action "Cancel" →
  `PendingIntent` to the service with `ACTION_CANCEL_ALL`. Summary at the end: "5 done, 1 failed"
  (normal importance), tap opens the Queue tab.
- Before each job: `freeBytes()` ≥ 2 × the plan's expected output (or ≥ input size for copies);
  else fail "Not enough free space: needs N MB."

### 11.2 Mac

Covered in §6.3: child processes, `powerSaveBlocker`, quit confirmation.
