## Findings for the fix wave

C1 [Important] packages/sieve-core/src/allowlist.ts:58-61: the registered-script exclusion treats a page entry as a PREFIX (`*://${hostname}${pathname}${search}*`) while every other place treats a page entry as an exact page: the allow-rule regex at :50 (`^url(#.*)?$`) and `isAllowed` at :12 (used by inject.ts:65, the popup and `youtubeAdsOn`). Scenario: the owner clicks "Pause on this page" on a home page such as `https://www.bbc.com/`: the exclusion pattern becomes `*://www.bbc.com/*`, so the generic CSS for ads, trackers, distraction, cookies and antiadblock plus the `deny-notifications` script stop on EVERY page of www.bbc.com (and in www.bbc.com iframes on other sites); inject.ts sees `/news/...` as not allowlisted and its `excluded[]` only looks at genericExcept and My filters hosts so it does not add the generic CSS back; those pages keep network blocking and site-specific hiding but silently lose generic ad/cookie/annoyance hiding and the notification blocker while the menu says blocking is on. Narrower form: `https://a.com/watch?v=1` also covers `?v=10...`. Probe: `excludePatterns([], ['https://www.bbc.com/'])` gives `['*://www.bbc.com/*']`, while `isAllowed('https://www.bbc.com/news', [page root])` is false. The plan prescribed `'*://a.com/p*'` (plan:347) so the per-task review followed it; no e2e checks a sibling page. Fix: drop the trailing `*` (Chrome compares a match-pattern path against path plus query; the hash is not part of it; `?` is literal); update allowlist.test.ts:72-80 and plan.test.ts:75,77; add an e2e check: with a root page entry, `/other` still hides `.adsbygoogle`; check the root case in Chrome specifically (a bare `/` path may be special there).

C2 [Minor] compile.ts:265-275 and apps/sieve/README.md:72: `trusted: true` does nothing in production and the README says the opposite. My filters pass `scriptlets: meta.scriptlets`; the build compiles the lists untrusted (build.mjs:83) so a `trusted-*` name is never in `meta.scriptlets`; line 265 throws "trusted-set-cookie isn't available in this build" before the trusted check at :272 runs; compile.test.ts:238-246 pins that refusal. README:72 says "`trusted: true`, so `trusted-*` scriptlets are allowed": false. Fix: correct the README and drop the dead option (or, if the owner wants trusted scriptlets, have the build ship the `trusted-*` functions).

C3 [Minor] packages/sieve-core/src/picker.ts:13-23 (`escapeIdent`) against compile.ts:120 (`rawLine.trim()`): `classList` splits only on ASCII whitespace so `class="ad&nbsp;"` gives the token `ad ` (U+00A0); `escapeIdent` keeps it raw (at or above 0x80); same for U+3000, U+FEFF, U+2028. The pick hides at once (pick-handler stores the raw selector) but on the next My filters save `www.x.com##div.ad ` recompiles as `div.ad`, hiding every `div.ad` on the host; a class made only of such a space becomes `div.` (invalid CSS: the pick silently stops hiding). Fuzz: 5,000 selectorFor outputs through compileFilters: 0 errors, but every change in meaning came from these characters. Fix: in `escapeIdent`, hex-escape any character matching `/\s/` (`\a0 `) as it already does for control characters.

C4 [Minor] packages/sieve-core/src/hosts.ts:2,11: the comment says the extra candidates "match nothing", but the drop-two-labels candidate of any host with three or more labels is `<first>.*` (`google.github.io` gives `google.*`, so the Distraction list's six `google.*` hide rules apply there; `amazon.*` and `yandex.*` rules would hit `amazon.<x>.<y>` hosts). Today's selectors are Google- or Amazon-specific so nothing visibly breaks. Fix: correct the comment (the shortcut can stay), or add the `-2` candidate only when the second-to-last label looks like a second-level suffix (co, com, org, net, gov, ac and similar).
