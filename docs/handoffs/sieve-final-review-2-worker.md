## Findings for the fix wave

W1 [Important] build.mjs:58, build.mjs:77, options.ts:49, README.md:71: a rebuild does NOT refresh the lists, but the settings page says it does and shows the wrong date. Line 58 skips the download whenever a cached copy exists unless `--refresh` is passed; `meta.builtAt` (line 77) is the build time, not the list date; the settings page says "Lists built on <today>. Rebuild Sieve to update them." The design's decided section says "Lists refresh when the extension is rebuilt" (spec:230) and README:71 says the same, while README:20 documents `--refresh`. Scenario: the worktree cache (`filters/cache/*.txt`) is from 6 Nov (list headers `Last modified 06 Nov 2026`); any build since shows "Lists built on 8 Nov 2026"; the owner sees adblock walls or YouTube ads come back, runs the build as the page says, nothing downloads, the date says fresh. Anti-adblock and YouTube rules go stale fastest. Fix: write `meta.listsAt` as the oldest cached list mtime (or the lists' `! Last modified`) and show that date with copy that names `--refresh`; or download by default and keep the cache only as the fallback (`download()` already falls back to it). Note: the owner's installed copy was built from a clean export of HEAD (no cache dir), so it downloaded fresh lists on 2026-11-08.

W2 [Minor] build.mjs:74: the build deletes `dist` BEFORE compiling (`rmSync(out)` before the compile loop; manifest.json and meta.json written only at lines 137-138). A compile or esbuild throw after `--refresh` (a list format change) leaves a dist with no manifest; the installed unpacked Sieve then fails at the next reload or Chrome restart ("Manifest file is missing") and "Remove and re-add" would lose settings and My filters (they live only in that extension's storage). Fix: build into `dist.next` and rename over `dist` at the end.

W3 [Minor] inject.ts:16-19 (and :60): `load()` caches a rejected fetch forever (the same bug counts.ts fixed in Task 1.7 m6). Scenario: the owner browses while a build runs; `dist/meta.json` is missing during the compile loop, the first page's `load('meta.json')` rejects and stays cached; every later page in that worker gets no site-specific hiding or scriptlets until the worker restarts (onRuleMatchedDebug events keep it alive). Fix: `.catch((e) => { files.delete(path); throw e; })`; same for `stored`. W2 also shrinks the window.

W4 [Minor] plan registrations (applied by blocking.ts:41-51) and background.ts:21: `about:blank`, `srcdoc` and `data:` frames get no generic CSS, no site-specific hiding and no notification blocker (registrations lack `matchOriginAsFallback`; inject's `onCommitted` listener filters to http(s)). The e2e page test/pages/yt-watch.html:18-20 relies on exactly this. Scenario: ad markup written into a friendly about:blank iframe (GPT non-SafeFrame creatives, Prebid) is never hidden inside the frame (usually the parent's container selectors hide the frame; small visible impact). Missing from README "Known limits". Fix: document it, or add `matchOriginAsFallback: true` (Chrome 119+, under the 128 minimum) to the registrations and to `scriptShape`.

Nits: build.mjs:18 and :104 `HOSTNAME` duplicates sieve-core's `isHost` and is looser (accepts `-a.com`, `a-.com`, `1.2.3`, `example.123`, labels over 63 chars; none in today's genericExcept; plan.ts:47 notes one pattern Chrome refuses voids the whole registration): use `isHost`. counts.ts:1 imports `../../../packages/ui/src/tokens.ts` across package roots (repo rule: import by package name; `@apps-hub/ui` is not in apps/sieve/package.json); picker.ts:2-3 and build.mjs:171 do the same. test/e2e.mjs 1,519 lines in one try: split by area (as picker-move.mjs already is).
