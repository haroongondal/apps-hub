## Findings for the fix wave

F1 [Important] apps/sieve/src/notify-deny.ts:2-6 and :9: denies notifications even on sites the owner has ALREADY allowed. `requestPermission` always returns 'denied' and `PushManager.prototype.subscribe` always rejects whatever `Notification.permission` is; e2e:154 grants the permission then e2e:241 expects `denied,denied,NotAllowedError`. A site that asks before showing a notification (OneSignal pattern) or needs a new push subscription (Firebase getToken, or after clearing site data) is told "denied" and stops, while Chrome still says Allowed. The only ways out are allowlisting the whole site (loses ad blocking there) or switching the feature off everywhere. Anti-goal 2. Fix: deny only while `Notification.permission === 'default'`; otherwise call the saved native functions (subscribe through the native when permission is 'granted'). Change e2e:241 to expect `granted` with the permission granted, and add a check with the default permission expecting `denied`.

F2 [Minor] packages/sieve-core/src/picker.ts:10,26 with apps/sieve/src/picker.ts:108: generated ids are kept though generated classes are dropped. `PLAIN_ID` accepts any id and `choose()` stops at one: `#yui_3_18_1_1_1700000000000_1234`, `#ember1234`, `#mui-12345` are accepted; the item hides now, and after a reload hides nothing because the id changed. Fix: apply the `generated()` digit rule to ids too and fall back to class or nth-of-type.

F3 [Minor] apps/sieve/src/popup.ts:127: always adds "Turn a list off in Settings to make room." to the error, though `blockingError` holds Chrome's raw message for any failure (a refused regex in My filters, too many dynamic rules, a script registration error); turning a list off fixes none of those and the raw text is not plain words. Fix: show the make-room advice only for the static rule-limit error; otherwise generic advice ("Open Settings and check My filters", or "Reload Sieve from chrome://extensions").

F4 [Minor] apps/sieve/src/yt-main.ts:40-49: `JSON.parse.toString()` returns the wrapper's own source (dist/yt-main.js:79-88 not minified), not `[native code]`. The lists' own json-prune scriptlet binds toString to the native (dist/scriptlets.js:763 `jsonParseWrapper.toString = native.toString.bind(native)`). YouTube's anti-adblock can detect Sieve with one check (anti-goal 4 risk), and the README's "behave as the browser's own" claims more than is true. Fix: bind both wrappers' toString to the natives' and add it to the e2e shape check.

F5 [Minor] popup.ts and options.ts duplicate `save`/`setList` (popup.ts:39-45 vs options.ts:18-20), `toggle` (popup.ts:47-48 vs options.ts:23-27), `count` (popup.ts:64 vs options.ts:30), with drifted error handling (popup `save` has no catch: unhandled rejection; options logs). The popup hard-codes list labels (popup.ts:121-123) that `NAMES` in lists.ts:3-10 holds; the popup shows "1234 ads", options "1,234 rules". Fix: one small shared module with save, setList, toggle (revert the switch and log on failure) and labels from NAMES. This also closes ledger minors 1.7 (dropped save promise, flipped switch) and 1.9 m7.

F6 [Minor, a11y] popup.ts:128-129, :164-166, :127: activating "Pause everywhere" or "Resume" from the keyboard drops focus to body (re-render restores focus by `data-id`, but `pause` no longer exists: map pause to resume and back). Every settings change rebuilds the whole menu and inserts a new `role="alert"` banner so a screen reader reads the error again: keep the banner node.

F7 [Minor, copy] popup.ts:57-60, :112: on pages Chrome will not let extensions script (chromewebstore.google.com) the picker button is enabled, `executeScript` fails, and the menu says "Reload this page, then try again.", which cannot help. When the error is "cannot be scripted" say "Sieve can't open the item picker on this page."

F8 [Minor, tests] apps/sieve/test/e2e.mjs is 95,130 bytes and 1,519 lines, all in one `try` (81-1510) with shared mutable state (m, s, pw, hits, list, My filters content): the first exception skips every later section and sections depend on state left by earlier ones (the `127.0.0.1##div.toast` coupling). Fix: split into per-area files (blocking, menu, picker, settings, panel, YouTube), each starting from known settings.
