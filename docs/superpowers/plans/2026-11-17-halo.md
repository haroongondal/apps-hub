# Halo stages 1–2 (spike + edge lights) Implementation Plan

> **For agentic workers:** Execute with `cd-engineering-tools:parallel-agents-coord` (owner's rule: never
> `superpowers:subagent-driven-development`), or `superpowers:executing-plans` when run inline. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Store-installable Halo app whose Kotlin service draws music-reactive edge lights (24 original
patterns, palette / album-art / wallpaper colours, screen-edge editor) with React Native settings screens.

**Architecture:** Expo app `apps/halo` + Expo local module `apps/halo/modules/halo-engine`. Pure Kotlin in
`core/` (JVM-tested) produces draw ops; `android/` holds the service, Visualizer tap, overlay window and Canvas
renderer. RN only edits one settings JSON document and renders status.

**Tech Stack:** Expo SDK 54, RN 0.81.5, TS 5.9 (erasable), Kotlin, `kotlinx-serialization-json` 1.8.1 (JsonElement
API only, no compiler plugin), JUnit 4.13.2, `@apps-hub/ui`.

**Spec:** `docs/superpowers/specs/2026-11-17-edge-visualizer-design.md`. Stages 3–5 get their own plan after the
stage 1 spike, because its result fixes the service type and start path they build on.

## Global Constraints

- Package `com.haroon.halo`, folder `apps/halo`, module `halo-engine` (Kotlin `expo.modules.haloengine`), release
  id and brand key `halo`, brand hue 190 (accent from the icon, AA contrast enforced by the ui test).
- Android only; `android.minSdkVersion=33` in `apps/halo/android/gradle.properties`.
- No ads, analytics, Firebase, billing, Play Services, closed SDKs; no new dependency beyond those in Tech Stack.
- Release build has no `INTERNET` permission; debug keeps it for Metro.
- Every edge overlay window: `TYPE_APPLICATION_OVERLAY`, `FLAG_NOT_TOUCHABLE | FLAG_NOT_FOCUSABLE |
  FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS`, `fitInsetsTypes = 0`, `layoutInDisplayCutoutMode = ALWAYS`,
  transparent, window `alpha` ≤ 0.8 (Android 12+ drops touches passing through a more opaque overlay).
- No frames requested while audio is silent and no animation runs. Draw time target < 4 ms per frame (p95).
- Never copy Muviz names, art or strings. Pattern names below are ours.
- RN copy: sentence case, plain words, no emoji, no ALL CAPS; colours and fonts only from `@apps-hub/ui`.
- Each new `*.test.ts` is listed in `apps/halo/package.json` `test`.
- Phone: claim `device:<ro.serialno>` with coord; install only via the Store; `pnpm release halo` is
  pre-approved (tell the owner each time); force-stopping `com.sparkine.muvizedge` before audio tests is
  pre-approved. Any other app's release (the Store included) needs the owner's go. No Claude attribution lines.

## Review Focus

1. Another visualizer app holds audio → status says so in plain words and the service retries; it never crashes.
   Test: `AudioWatchTest.blockedAfterInitFailure`.
2. Settings JSON from an older or hand-edited build (missing fields, wrong types, out-of-range numbers, unknown
   pattern id) → every field falls back or clamps; never throws. Test: shared fixture cases in Task 4.
3. Screen rotates or resolution changes while lights run → path rebuilt from new size, nothing drawn off-screen.
   Test: `EdgePathTest.rebuildsForLandscape` + the pattern bounds test runs on both 1080×2400 and 2400×1080.
4. Album art missing, tiny or all-black → palette falls back to the custom palette, colours are lifted so the
   edge stays visible. Test: `QuantizeTest.blackArtIsLifted`, `QuantizeTest.emptyFallsBack`.
5. Silence between tracks → frames stop (idle), resume on audio without a stale burst. Test:
   `SpectrumTest.silenceDecaysToZero` + `AudioWatchTest.idleWhenSilent`.

### Task 5: Spectrum (FFT → bands, level, beat)

**Files:** `core/Spectrum.kt`, test `core/SpectrumTest.kt`.

**Interfaces:** `class Spectrum(bandCount: Int = 32)`; `fun update(fft: ByteArray, nowMs: Long): SpectrumFrame`;
`class SpectrumFrame(val bands: FloatArray, var level: Float, var beat: Boolean)` (reused instance, values 0..1).
FFT layout (Visualizer.getFft): `[0]` DC real, `[1]` Nyquist real, then `re,im` pairs for k=1..n/2-1.
Bands log-spaced over bins 1..n/2-1; value `log10(1+mag)/log10(182)` clamped; attack 0.6 per frame toward a
higher value, release 3.0 units/s; beat = level > 1.4 × 1 s running mean and level > 0.2, 200 ms refractory.

- [ ] Step 1: Tests: `silenceDecaysToZero` (after loud frames, 1 s of zeros → all bands < 0.02, no beat);
  `singleBinLandsInItsBand` (spike at bin k → max band is `bandOf(k)`); `valuesInUnitRange` (random bytes);
  `burstAfterQuietIsBeat`; `noBeatWithinRefractory`. Run → FAIL.
- [ ] Step 2: Implement; run → PASS. Commit.

### Task 7: Pattern API, draw list and the first 6 patterns

**Files:** `core/DrawList.kt`, `core/Pattern.kt`, `core/patterns/{PulseRing,CornerBloom,SpectrumRim,Comet,EmberDrift,Ripple}.kt`,
`core/Patterns.kt` (registry), `core/RandomMotion.kt`, tests `core/PatternsTest.kt`, `core/RandomMotionTest.kt`.

**Interfaces:**
```kotlin
enum class Family { LIGHTS, LINES, PARTICLES, WAVES }
class PatternParams(thicknessPx, speed, spread, glow, paddingPx, roundness, mirrored, clockwise) // from Settings, dp→px by caller
class FrameInput(val path: EdgePath, val spectrum: SpectrumFrame, val timeMs: Long, val dtMs: Long,
                 val params: PatternParams, val colors: IntArray /*1..4 ARGB*/)
interface Pattern { val id: String; val family: Family; fun draw(input: FrameInput, out: DrawList) }
class DrawList { fun clear(); fun polyline(xy: FloatArray, n: Int, color: Int, widthPx: Float, glow: Float, closed: Boolean);
                 fun dot(x: Float, y: Float, radiusPx: Float, color: Int, glow: Float); val opCount: Int }
object Patterns { val all: List<() -> Pattern>; fun create(id: String): Pattern /*unknown → pulse-ring*/ }
object RandomMotion { fun fill(bands: FloatArray, timeMs: Long, seed: Int) } // smooth value noise, 0..1
```
DrawList stores ops in growable primitive arrays reused across frames (no per-frame allocation after warm-up).
Patterns keep their own particle state; randomness comes from a seeded `java.util.Random`.
Patterns: `pulse-ring` (Lights: whole edge, brightness = level), `corner-bloom` (Lights: four corner glows by band
groups), `spectrum-rim` (Lines: bars along the edge, inward length = band), `comet` (Lines: bright tail racing
round the edge, speed by level), `ember-drift` (Particles: beats spawn embers that drift inward and fade),
`ripple` (Waves: sine offset along the edge, amplitude by bands). `mirrored` reflects about the vertical axis;
`clockwise=false` reverses t.

  `opCount` ≤ 4096; same seed → identical ops (determinism); unknown id → `pulse-ring`; ids unique; 6 patterns
  cover all 4 families. `RandomMotionTest`: values in [0,1], continuous (adjacent 16 ms frames differ < 0.1).
  Run → FAIL.
