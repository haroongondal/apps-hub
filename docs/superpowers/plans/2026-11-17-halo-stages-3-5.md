# Halo stages 3–5 Implementation Plan (stage 3 in full; stages 4–5 outline)

> **For agentic workers:** Execute with `cd-engineering-tools:parallel-agents-coord` (owner's rule: never
> `superpowers:subagent-driven-development`). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Halo 0.4.0 — per-app notification edge flashes with styles, reminders and quiet hours, plus hide/pause
rules — then (after the phone gate) the always-on screen (0.5.x) and the extras (0.6.0).

**Architecture:** Same split as stages 1–2: pure Kotlin decisions in `core/` (JVM-tested) → platform glue in
`android/` → RN settings screens via `@apps-hub/ui`. All edge effects share the one overlay window and frame loop:
`EdgeView` gains an event layer drawn over the music pattern.

**Tech Stack:** unchanged (Expo SDK 54, RN 0.81.5, Kotlin, kotlinx-serialization-json JsonElement API, JUnit 4).

**Spec:** `docs/superpowers/specs/2026-11-17-halo-stages-3-5-design.md` (approved 2026-11-17) on top of
`docs/superpowers/specs/2026-11-17-edge-visualizer-design.md` (§13 = phone results).

## Global Constraints

- All of the stages 1–2 plan's Global Constraints still apply (`docs/superpowers/plans/2026-11-17-halo.md`), incl.
  overlay alpha ≤ 0.8, no per-frame allocations, idle rule, no Muviz names/art, `@apps-hub/ui` only, no attribution
  lines, pathspec commits, `pnpm release halo` pre-approved (re-fetch manifest.json after each release).
- Settings document stays `version: 1`; every new block is optional with defaults, so 0.3.x documents still load.
  Every new block gets shared-fixture cases checked by BOTH the Kotlin and TS tests (literal comparison).
- Never store or log notification titles/text. Only package names, counts, colours.
- New permission: `QUERY_ALL_PACKAGES` only. No `READ_PHONE_STATE`.
- Module code root: `apps/halo/modules/halo-engine/android/src/main/java/expo/modules/haloengine/` (below: `core/…`,
  `android/…`); tests mirror it under `src/test/java/...`.

## Review Focus

1. A chat app posts 50 notifications in a minute → flashes coalesce (at most one running flash per app, a new post
   restarts it), memory bounded. Test: `NotifyRulesTest.burstCoalesces`, `EdgeEventsTest.queueIsBounded`.
2. Quiet hours that cross midnight (22:00–07:00) and equal start/end (= off) behave as a person expects. Test:
   `QuietHoursTest.crossesMidnight`, `QuietHoursTest.equalMeansOff`.
3. A package in the per-app list is uninstalled, or a new app appears → no crash; unknown apps use the defaults.
   Test: `NotifyRulesTest.unknownAppUsesDefaults`.
4. A notification is removed (read elsewhere) before its reminder fires → no reminder. Test:
   `NotifyRulesTest.removedCancelsReminder`.
5. Music playing during a call, then the call ends → lights hidden during the call, back after. Test:
   `RulesTest.callHidesThenRestores`.
