# Halo stages 3–5 Implementation Plan (stage 3 in full; stages 4–5 outline)

> **For agentic workers:** Execute with `cd-engineering-tools:parallel-agents-coord` (owner's rule: never
> `superpowers:subagent-driven-development`). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Halo 0.4.0 — per-app notification edge flashes with styles, reminders and quiet hours, plus hide/pause
rules — then (after the phone gate) the always-on screen (0.5.x) and the extras (0.6.0).

**Architecture:** Same split as stages 1–2: pure Kotlin decisions in `core/` (JVM-tested) → platform glue in
`android/` → RN settings screens via `@apps-hub/ui`. All edge effects share the one overlay window and frame loop:
`EdgeView` gains an event layer drawn over the music pattern.

**Tech Stack:** unchanged (Expo SDK 54, RN 0.81.5, Kotlin, kotlinx-serialization-json JsonElement API, JUnit 4).

**Spec:** `docs/superpowers/specs/2026-11-17-halo-stages-3-5-design.md` (approved 2026-11-17) on top of
`docs/superpowers/specs/2026-11-17-edge-visualizer-design.md` (§13 = phone results).

## Global Constraints

- All of the stages 1–2 plan's Global Constraints still apply (`docs/superpowers/plans/2026-11-17-halo.md`), incl.
  overlay alpha ≤ 0.8, no per-frame allocations, idle rule, no Muviz names/art, `@apps-hub/ui` only, no attribution
  lines, pathspec commits, `pnpm release halo` pre-approved (re-fetch manifest.json after each release).
- Settings document stays `version: 1`; every new block is optional with defaults, so 0.3.x documents still load.
  Every new block gets shared-fixture cases checked by BOTH the Kotlin and TS tests (literal comparison).
- Never store or log notification titles/text. Only package names, counts, colours.
- New permission: `QUERY_ALL_PACKAGES` only. No `READ_PHONE_STATE`.
- Module code root: `apps/halo/modules/halo-engine/android/src/main/java/expo/modules/haloengine/` (below: `core/…`,
  `android/…`); tests mirror it under `src/test/java/...`.

## Review Focus

1. A chat app posts 50 notifications in a minute → flashes coalesce (at most one running flash per app, a new post
   restarts it), memory bounded. Test: `NotifyRulesTest.burstCoalesces`, `EdgeEventsTest.queueIsBounded`.
2. Quiet hours that cross midnight (22:00–07:00) and equal start/end (= off) behave as a person expects. Test:
   `QuietHoursTest.crossesMidnight`, `QuietHoursTest.equalMeansOff`.
3. A package in the per-app list is uninstalled, or a new app appears → no crash; unknown apps use the defaults.
   Test: `NotifyRulesTest.unknownAppUsesDefaults`.
4. A notification is removed (read elsewhere) before its reminder fires → no reminder. Test:
   `NotifyRulesTest.removedCancelsReminder`.
5. Music playing during a call, then the call ends → lights hidden during the call, back after. Test:
   `RulesTest.callHidesThenRestores`.

**Files:** Modify `core/Settings.kt`, `modules/halo-engine/src/settings.ts`, `modules/halo-engine/fixtures/settings.cases.json`,
`src/test/.../core/SettingsTest.kt`, `apps/halo/src/__tests__/settings.test.ts`.

**Interfaces (Produces):**
```ts
type FlashStyle = 'pulse' | 'sweep' | string /* any pattern id */;
interface AppNotify { on: boolean; colour: string | null /* '#RRGGBB' or null = from icon */ }
interface Notify { enabled: boolean /*true*/; apps: Record<string, AppNotify> /*{}*/; defaultOn: boolean /*true*/;
  style: FlashStyle /*'pulse'*/; repeat: number /*1..5, 2*/; durationMs: number /*500..5000, 1500*/;
  reminderMin: 1 | 2 | 5 | 10 | 15 | null /*null*/; wakeScreen: boolean /*false (used in stage 4)*/;
  quiet: { on: boolean /*false*/; start: string /*'22:00'*/; end: string /*'07:00'*/ } }
interface Rules { apps: string[] /*[]*/; fullscreen: boolean /*true*/; landscape: boolean /*false*/;
  calls: boolean /*true*/; batterySaver: boolean /*true*/; pocket: boolean /*false*/ }
// Settings gains notify: Notify, rules: Rules
```
Kotlin mirrors as `SettingsNotify`, `AppNotify`, `SettingsQuiet`, `SettingsRules` (data classes, same defaults).
Package keys: `^[a-zA-Z0-9_.]{1,200}$` else dropped; times `^([01]\d|2[0-3]):[0-5]\d$` else default; `reminderMin`
not in the set → null; `style` = 'pulse' | 'sweep' | pattern-id regex, else 'pulse'; at most 500 app entries.

### Task 3.2: QuietHours and NotifyRules (core)

**Files:** Create `core/QuietHours.kt`, `core/NotifyRules.kt`, tests `QuietHoursTest.kt`, `NotifyRulesTest.kt`.

**Interfaces (Produces):**
```kotlin
object QuietHours { fun active(on: Boolean, start: String, end: String, minuteOfDay: Int): Boolean }
class PostedNote(val key: String, val pkg: String, val ongoing: Boolean, val importance: Int,
                 val groupSummary: Boolean, val category: String?, val postedAtMs: Long)
class FlashDecision(val pkg: String, val colour: Int? /*null = from icon*/, val style: String, val repeat: Int, val durationMs: Long)
class NotifyRules(private val ownPkg: String) {
  fun onPosted(n: PostedNote, s: SettingsNotify, minuteOfDay: Int, nowMs: Long): FlashDecision?
  fun onRemoved(key: String)
  fun onUnlocked(nowMs: Long)                       // clears reminder state
  fun dueReminders(s: SettingsNotify, minuteOfDay: Int, nowMs: Long): List<FlashDecision> // each key at most once per period
  fun nextReminderAtMs(s: SettingsNotify): Long?    // for scheduling a Handler
}
```
Filters: skip ownPkg, ongoing, `importance < 3` (IMPORTANCE_DEFAULT), group summaries; app off (explicit entry
`on=false`, or no entry and `defaultOn=false`) → null; quiet hours → null (and no reminders). Colour: entry colour
parsed, else null. Coalescing: a key already tracked updates its time, no duplicate tracking.

- [ ] Step 1: Tests: `crossesMidnight`, `equalMeansOff`, `insideAndOutsideWindow`; `skipsOwnOngoingSilentSummary`,
  `appOffAndDefaultOff`, `unknownAppUsesDefaults`, `quietSuppresses`, `burstCoalesces` (50 posts same key → 1 tracked),
  `reminderEveryPeriodUntilUnlock`, `removedCancelsReminder`, `noRemindersWhenNull`. FAIL → implement → PASS. Commit.

### Task 3.3: Edge events (flash, sweep) in the renderer

**Files:** Create `core/EdgeEvents.kt` + `EdgeEventsTest.kt`; modify `android/EdgeView.kt`, `android/HaloService.kt`.

**Interfaces (Produces):**
```kotlin
class EdgeEvents(cap: Int = 8) {
  fun flash(d: FlashDecision, colour: Int, nowMs: Long)      // replaces a running flash of the same pkg
  fun active(nowMs: Long): Boolean
  fun draw(path: EdgePath, params: PatternParams, nowMs: Long, out: DrawList) // appends ops; style 'pulse' = whole rim
     // brightness pulses `repeat` times over durationMs; 'sweep' = bright arc travels once round per repeat;
     // pattern id = that pattern driven by a synthetic spectrum for durationMs (Patterns.create, reused instance)
}
// HaloService companion: fun flash(ctx: Context, d: FlashDecision, colour: Int)
```
EdgeView: events draw after the music pattern into the same DrawList; frame loop runs while `animate || events.active`;
if the overlay is not shown (lights disabled), a flash shows the window for its duration only when `notify.enabled`
(overlay add/remove as today); on the always-on screen (stage 4) the same class is reused.

- [ ] Step 1: Tests `pulseDrawsThenEnds` (no ops after durationMs), `sweepCoversRim`, `samePkgReplaces`,
  `queueIsBounded` (20 pkgs → ≤ 8), `opsInBounds`. FAIL → implement → PASS.
- [ ] Step 2: Wire into EdgeView/HaloService; emulator: `cmd notification post` → flash visible; idle again after. Commit.

### Task 3.5: Hide/pause rules

**Files:** Create `core/Rules.kt` + `RulesTest.kt`, `android/RuleInputs.kt`; modify `HaloService.kt`, module
(`openPermission('usage')`), `src/index.ts`, `setup.ts` (usage row only when `rules.apps` non-empty).

**Interfaces (Produces):**
```kotlin
class RuleState(var foregroundPkg: String?, var fullscreen: Boolean, var landscape: Boolean, var inCall: Boolean,
                var batterySaver: Boolean, var pocket: Boolean)
object Rules { fun hidden(s: SettingsRules, st: RuleState): Boolean }
```
RuleInputs: foreground app via `UsageStatsManager.queryEvents` polled every 1 s only while `rules.apps` is non-empty
and access granted; fullscreen via a 1×1 non-touchable overlay view reading `WindowInsets.isVisible(statusBars())`;
landscape from configuration; calls via `AudioManager.addOnModeChangedListener` (IN_CALL / IN_COMMUNICATION /
RINGTONE); battery saver via `PowerManager` + broadcast; pocket via proximity sensor (registered only while lights or
flashes are active and `rules.pocket`). Hidden → overlay view `visibility = GONE` and frame loop stopped; Visualizer kept.

- [ ] Step 1: Tests `noRulesNeverHides`, `eachRuleHides`, `callHidesThenRestores`, `appListMatchesForeground`.
  FAIL → implement → PASS.
- [ ] Step 2: Wire; emulator: rotate (landscape on), fullscreen video, fake call mode (`cmd audio set-mode`? else
