# Sieve Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One private Chrome MV3 extension that does what AdBlock, Enhancer for YouTube and IDM Integration do, built in phases. This plan covers phase 0 (the YouTube download spike) and phase 1 (the shell and blocking) in full. Phases 2 to 5 are outlines, planned after the spike.

**Architecture:** Pure logic lives in `packages/sieve-core` and is tested with `node --test`. The extension lives in `apps/sieve` (Strongroom extension pattern: esbuild bundles, static files, `packages/ui` web tokens, playwright-core e2e). Filter lists are compiled at build time into `declarativeNetRequest` static rulesets (one per feature), plus generic CSS files and per-host cosmetic and scriptlet maps. The service worker turns settings into a "blocking plan": which rulesets are on, which content scripts are registered, and which dynamic rules exist. It applies that plan by diffing against Chrome's current state.

**Tech Stack:** TypeScript (erasable), esbuild 0.28.2, `@adguard/dnr-converter` 2.0.0 (GPL-3.0-only), `@adguard/agtree` 4.3.0 (MIT), `@adguard/scriptlets` 2.5.1 (GPL-3.0), `@types/chrome` (MIT, types only), playwright-core and Chrome for Testing (already on this Mac), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-06-sieve-design.md` (approved 2026-11-06). Progress: `docs/handoffs/sieve.md`.

## Global Constraints

- Chrome only, Manifest V3, `"minimum_chrome_version": "127"`, loaded unpacked from `apps/sieve/dist/`. Never published.
- Erasable TypeScript only (no enums, namespaces or parameter properties). Import with the `.ts` extension. List every new `*.test.ts` in its package's `test` script.
- UI uses `packages/ui/web/tokens.css` and `base.css` with `<html data-brand="sieve">`, the `--c-*` variables and `.ui-*` classes. No hand-rolled colours or fonts.
- Copy is sentence case and active voice, with no emoji icons and no ALL-CAPS. Errors say what happened and how to fix it.
- Privacy: no telemetry and no remote calls of our own. The extension's only traffic is the pages the owner visits and the files they download. The build fetches filter lists on the Mac; the extension never does.
- No code is copied from IDM, Enhancer or AdBlock. Dependencies may be GPL. Record each licence in `apps/sieve/README.md`.
- Chrome limits: 30,000 guaranteed enabled static rules (a shared pool beyond that), at most 1,000 regex rules per ruleset, 50 enabled static rulesets, and 30,000 dynamic rules.
- Defaults: every blocking feature is on, except AI search summaries (off).
- Automated tests never use the owner's Chrome profile. Signed-in checks are an owner checklist.
- Commits go on branch `sieve` only, with no Co-Authored-By or "Generated with" lines.
- The four anti-goals are acceptance criteria for every phase:
  1. browsing does not slow down
  2. sites do not break (one per-site switch turns off all blocking there)
  3. downloads are never lost
  4. YouTube does not feel janky

## Review Focus

1. **An allowlisted or paused site still loses content.** Generic CSS comes from a registered content script, and scriptlets are injected separately, so the allowlist must reach both, not only the network rules. Expect: on an allowlisted site, the ad request loads, the `.adsbygoogle` element is visible, and no scriptlet runs. Pinned in Task 1.6's e2e.
2. **The service worker is stopped mid-session.** Chrome kills idle workers. Expect: blocking, the allowlist and the per-tab counts all survive a stop. Pinned in Tasks 1.5 and 1.7 (e2e stops the worker over CDP).
3. **Ads inside iframes.** Expect: an ad request made from an iframe is blocked, and an ad element inside a same-origin iframe is hidden. On an allowlisted site, the iframe's ad request loads. Pinned in Task 1.6's e2e.
4. **Bad text in My filters.** This covers garbage lines, a regex Chrome refuses, and a huge paste. Expect: valid lines are saved and applied, bad lines are listed by line number, and the rules that were already on stay on if Chrome rejects the update. Pinned in Tasks 1.3 and 1.9.
5. **Unusual hosts and non-web pages.** This covers `www.` subdomains, `google.*` style filters, IP addresses, `localhost`, punycode hosts, and `chrome://` or `file://` tabs. Expect: correct matching, and the menu says "Sieve doesn't run on this page" instead of failing. Pinned in Tasks 1.3 (`hostCandidates`) and 1.7.

## Phase 0: YouTube download spike (throwaway)

The spike answers four questions before the main build: (Q1) can we get 1080p and above plus audio, (Q2) at full speed, (Q3) signed in as the owner, and (Q4) how fast are split downloads compared with a plain Chrome download, on one HTTP/1.1 server and one HTTP/2 server? It is plain JavaScript with no build step, kept in `apps/sieve/spike/`. It is committed so a later session can rerun it, and deleted when phase 5 replaces it. It writes no tests: its output is measurements, recorded in the handoff file.

Test video: `https://www.youtube.com/watch?v=aqz-KE-bpKQ` (Blender's "Big Buck Bunny 60fps 4K", public, offered up to 2160p). If it is unavailable, use any public video offered at 2160p, and record the ID.
